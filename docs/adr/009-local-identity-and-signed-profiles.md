# ADR 009 — Local identity and narrowly versioned signed commerce

Status: implemented locally, 2026-11-04. Supersedes v0.1's synthetic-cookie and handwritten-MCP implementation descriptions; does not authorize paid services, public hosting or live payments.

Use a revocable database-backed browser session. The optional local Keycloak profile provides OIDC Code + PKCE S256 with one-use browser-bound state, nonce, configured issuer/JWKS trust, audience checks and provisioned tenant/role membership. Provider tokens are encrypted at rest; browser JavaScript receives only actor context and a CSRF token. Logout revokes this application's session; it does not claim global identity-provider logout. Role/revocation changes are observed through bounded short-lived provider tokens and refresh, not instant cross-system invalidation.

Use MCP Python SDK 2.3.0 Streamable HTTP and typed read-only tools. OIDC MCP access requires a resource-audience access token; a browser cookie is not sufficient. Demo mode also permits an explicitly local opaque bearer session for development. No approval, payment or arbitrary browser tools are exposed by MCP.

Use AP2 v0.2.0 SDK primitives at revision b4587ac1d055888a73b4b21750973cffba961793. Explicit dependency overrides retain current audited cryptography/jwcrypto/Pydantic/pytest versions. Exclude the SDK facade that logs signed presentations and general intermediate delegation. The local profile uses explicit wallet/merchant/delegate keys, ES256, one root or one open-to-closed terminal hop, exact checkout hashes, current backend grants and encrypted retained artifacts. The pinned examples' `example+sd-jwt` root type is a declared local-profile choice, not a general credential-format interoperability guarantee. Merchant signatures are independently verified before mandate acceptance.

Keep RFC 9421 Ed25519 request recognition separate from authority. Cover method, authority, path, query, content type, agent identity, business key and content digest; enforce purpose/time and consume a durable nonce. This uses TAP-style purpose tags but no Visa enrollment or network acceptance is claimed.

Freeze UCP at release 2026-08-25 and ACP at spec 2026-04-17. Offline bundled official schemas, licenses and hashes live in the package. The outbound adapters implement five operation contracts and a durable command journal. Unknown completion is inquired before any retransmission; default policy never repeats completion. UCP identical-key retry is an explicit configured-peer policy. Merchant `completed` maps to order placed, with payment/fulfillment left unknown. These adapters are contract-tested against synthetic peers; the current shopper graph still uses its internal virtual-kiosk merchant. External commerce routing and merchant enrollment are separate gates.

The owner subsequently asked about pharmacy facilities and users. The implemented domain remains general retail/virtual-kiosk commerce. A pharmacy-specific OTC/pickup or prescription-coordination workflow has not yet been selected or implemented. Shared infrastructure remains useful; relabeling a kiosk is not evidence of pharmacy workflow support.
